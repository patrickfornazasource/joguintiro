# F0-02: Servidor mínimo com WebSocket

## Objetivo

Ter um servidor Node que aceita conexões WebSocket e serve o jogo pronto.

## Contexto

O multiplayer real só vem na Fase 3. Aqui só a base, para nunca precisar reestruturar depois.

## Passo a passo

1. Adicionar dependência `ws`.
2. Criar `server/index.js`: servidor `http` na porta `process.env.PORT || 8787`.
3. Rota `GET /health` responde `{"ok":true}`.
4. Se a pasta `dist/` existir, servir arquivos estáticos dela (com tipos MIME corretos e `index.html` como padrão). Sem frameworks.
5. WebSocket no caminho `/ws` (`WebSocketServer` com `noServer` + evento `upgrade`). Ao conectar, enviar `{"t":"hello","v":1}`. Responder `{"t":"pong"}` a `{"t":"ping"}`.
6. Em `vite.config.js`, proxy de `/ws` para `ws://localhost:8787` com `ws: true`.
7. Scripts: `server` (node --watch server/index.js) e `start` (node server/index.js).

## Arquivos previstos

- `server/index.js`
- `vite.config.js`
- `package.json`

## Pronto quando

- [ ] `npm run server` sobe na 8787 e `curl localhost:8787/health` responde ok.
- [ ] Após `npm run build`, `npm start` serve o jogo em http://localhost:8787.
- [ ] Um cliente WebSocket em `/ws` recebe `hello` e responde ao `ping`.
- [ ] `npm test` e `npm run build` passam (quando já existirem).
- [ ] Nenhum número de balanceamento fora de `shared/constants.js`.

## Como verificar

```bash
npm run build
(npm start &) ; sleep 1 ; curl -s localhost:8787/health
```
